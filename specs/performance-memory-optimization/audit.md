# 性能与内存审计报告

## 审计范围

- 对 `miniprogram/` 与 `cloudfunctions/` 的 272 个项目文件进行了目录、调用、查询、生命周期和资源模式扫描。
- 深入检查了启动、首页、个人中心、报名、专家评审、作品画册、聚合云函数路由、首页数据函数、入围/获奖查询和画册索引函数。
- 未读取或修改生产数据库内容，未调用管理类写函数；云函数部署结果在后续部署记录中补充。

## 已完成的性能优化

1. 应用启动只计算一次云环境，并在异步登录前初始化全局状态。
2. OpenID 云请求支持 Promise 复用，个人中心不再固定等待 2 秒，也不会在首次 `onLoad/onShow` 重复拉取数据。
3. 首页页面避免并发重复请求，并在页面卸载后忽略无效界面更新。
4. 首页云函数并行读取预约设置、公告和轮播，并限制公告/轮播字段。
5. `quickstartFunctions` 的大量子处理器改为按请求类型加载，减少冷启动同步解析和常驻模块数量。
6. 入围与获奖查询限制为一条记录，并只读取返回所需字段。
7. 画册不再把完整页索引复制进渲染层；作品和页码使用 `Map` 索引，翻页由线性查找改为常数时间查找。
8. 画册索引云函数不再返回作者、学校、指导教师的重复原字段和映射字段。
9. 专家列表和评分页增加请求进行中保护，避免首次进入重复请求及按钮/重试并发。

## 内存泄漏检查

### 已修复

- 画册翻页动画定时器集中登记，并在卸载时全部清理。
- 画册音频加载失败时销毁音频实例；正常卸载仍执行 `destroy()`。
- 画册卸载时不再调用无意义的 `setData`，直接释放逻辑层缓存和索引引用。
- 画册初始化异步返回后先检查页面是否仍存活。
- 个人中心延迟刷新定时器在隐藏和卸载时清理。
- 个人中心、专家列表和评分页在卸载后不再发起计划中的重试或执行大对象 `setData`。
- 专家详情与评分提交分别维护进行中状态，减少并发回调持有页面实例。

### 未发现持续泄漏

- 已注册页面中未发现 `setInterval`。
- 未发现未配对的全局 `wx.on*` 监听器。
- 唯一的 `InnerAudioContext` 位于画册，已有明确销毁路径。
- 其余 `setTimeout` 主要是 1–2 秒的成功提示/导航延迟，会自行结束，不属于持续泄漏。

### 需要手动观察

- 画册仍需保存全部作品展示数据以维持无等待翻页和全文搜索；已移除渲染层重复索引并减少字段重复，但真机内存峰值应继续观察。
- 图片原图预览由微信原生 `previewImage` 管理，页面只能释放自身保存的 URL 引用，系统图片解码缓存需以真机内存面板为准。
- 网络请求本身无法在所有基础库版本中可靠取消，因此采用“请求完成但页面销毁后不再更新界面”的兼容策略。

## 已处理的既有问题

- 删除了无实现、无前端调用的 `assignVideoNumbers` 残留路由，避免误调用时抛出模块缺失异常。
- 未注册页面 `pages/user-center` 的可选链已改为传统空值判断，兼容较旧基础库。
- 仓库存在大量用户未提交文件和改动，本次未回滚、删除或整理。

## 本地验证结果

- 所有本次修改的 JavaScript 文件均通过 `node --check`。
- 93 个非 `node_modules` JSON 文件均可被标准 JSON 解析器读取。
- 聚合云函数未知路由最小调用测试通过，保持原有错误返回。
- 路由静态检查确认 54 个模块引用中只有上述既有 `assignVideoNumbers` 缺失。
- `git diff --check` 未发现新增空白错误，仅提示仓库原有的 Windows 行尾转换设置。
