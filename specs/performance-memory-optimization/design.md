# 性能与内存优化设计

## 1. 设计原则

- 只优化实现方式，不改变业务入口、校验条件、返回字段和数据库语义。
- 优先采用局部、可回退、可静态验证的改动。
- 不引入新的运行时依赖，不改变基础库版本，不重构页面视觉层。
- 对已有未提交改动使用小范围补丁，避免覆盖用户代码。

## 2. 基线结论

- 小程序启动时先调用异步登录，再初始化 `globalData`，存在极端回调竞态和重复登录调用缺少复用的问题。
- 首页云函数依次读取预约设置、公告和轮播，三者互不依赖，可并行；查询结果也可限制字段。
- `quickstartFunctions` 在冷启动时同步加载大量子模块，绝大多数模块与单次请求无关，会增加冷启动时间和内存占用。
- 入围/获奖查询只需要一条记录，但查询未显式 `limit(1)`，且会传输不需要的字段。
- 画册已具备缓存释放和音频销毁逻辑，但翻页动画使用未登记的一次性定时器；页面快速退出时仍可能执行回调。
- 个人中心和部分表单页有异步加载与延迟刷新，页面卸载后仍可能继续 `setData`。
- 大型管理员函数会重写集合，不属于本次低风险性能修改范围，只审计不执行。

## 3. 前端方案

### 3.1 应用启动

- 在启动云调用前初始化 `globalData`。
- 为 OpenID 请求增加进行中 Promise 复用，避免未来多页面重复触发时产生并发登录请求。
- 优先复用本地缓存中的 OpenID，同时后台保持现有云函数身份确认语义。

### 3.2 页面异步生命周期

- 对高负载页面增加页面存活标志，卸载后不再执行非必要 `setData`。
- 对页面创建的一次性定时器集中登记，并在卸载时清理。
- 不取消已经提交到云端的业务写操作，仅阻止页面销毁后的界面更新。

### 3.3 作品画册

- 将翻页动画定时器集中管理，避免卸载后回调持有页面实例。
- 保持现有滑动窗口、缓存释放、预览图片释放和音频销毁策略。
- 搜索结果继续限制为 20 条，不扩大常驻数据。

### 3.4 首页与个人中心

- 首页请求增加并发去重和卸载保护。
- 个人中心保留现有并行请求，仅补充延迟任务和异步回调的释放边界。
- 不增加会造成数据陈旧的长时间页面缓存。

## 4. 云函数方案

### 4.1 聚合路由冷启动

- 将 `quickstartFunctions` 顶层子模块加载改为按 `event.type` 延迟加载。
- Node.js 模块缓存会复用已加载处理器，因此热调用不重复解析模块。
- 保留全部现有 `event.type` 名称、调用参数与返回值。

### 4.2 首页数据

- 预约设置、公告与轮播查询并行执行。
- 为公告和轮播增加字段投影，仅读取映射阶段使用的字段。
- 保留单项查询失败时返回空数组、预约默认开启的现有容错行为。

### 4.3 状态查询

- 入围和获奖查询增加 `limit(1)` 与字段投影。
- 保留姓名、手机号匹配逻辑和现有证书返回字段。

## 5. 验证策略

- JSON 文件使用解析检查。
- 改动的 JavaScript 使用 `node --check`；小程序特有 API 仅做语法检查，不在 Node 中执行。
- 使用静态调用图确认 `quickstartFunctions` 每个路由仍有对应处理器。
- 复查定时器创建与清理数量、媒体对象销毁路径、页面卸载后的异步写界面路径。
- 不调用写数据库函数、不部署云函数、不运行 `miniprogram-ci` 上传。

## 6. 手动验证建议

- 冷启动后检查首页轮播、公告和预约入口状态。
- 反复进出画册并快速翻页，观察内存曲线、音效和动画复位。
- 检查报名、送件、个人中心、入围与获奖查询。
- 检查专家登录、列表、评分与管理员面板只读展示。
