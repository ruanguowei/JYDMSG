# 2026 升级阶段 0：基线与环境隔离设计

## 环境选择

环境选择只由微信小程序运行版本决定：正式版使用生产环境，开发版和体验版使用测试环境。若读取版本失败，继续使用测试环境作为安全降级。

`app.js` 仍只初始化一次 `wx.cloud`，并把实际 `cloudEnv` 与 `envVersion` 保存到 `globalData`。管理员面板只展示这两个运行时值，不自行重新推测环境。

## 变更边界

- `envList.js`：恢复自动环境映射。
- 管理员面板：显示运行环境，不改变任何管理操作接口。
- 离线测试：模拟三种 `envVersion` 验证映射。
- `specs/2026-upgrade-stage-0/`：保存需求、设计、任务、审计和调用关系。

## 安全策略

- 本阶段不调用任何写云资源工具。
- 生产盘点只读取集合结构、记录数和存储对象清单。
- 文档只记录汇总，不复制姓名、手机号、身份证号等个人信息。
- 工作区已有修改全部保留；阶段 0 只修改明确列出的文件。

## 验证策略

- 使用 Node 测试模拟 `develop`、`trial`、`release`。
- 使用 `node --check` 验证改动 JavaScript。
- 使用现有离线冒烟测试验证页面、路由、OpenID 和资源清理约束。
- 对生产集合重新执行只读条数核对，不运行任何业务云函数。

## 测试环境恢复门禁

如果测试环境 ID 不在 CloudBase 当前账号的环境列表中，开发工作必须停止在只读或离线验证范围。不得将开发版临时切回生产环境。恢复路径按优先级为：

1. 确认原测试环境是否属于其他账号，并恢复当前账号访问权限。
2. 确认原测试环境是否处于隔离或过期状态并进行恢复。
3. 前两项均不可行时，单独确认套餐和费用后创建新测试环境，再更新配置。
